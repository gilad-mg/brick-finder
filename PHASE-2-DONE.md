### Section 2 — AI image search

- **Backend choice:** Brickognize. Verified live via `WebFetch` of `https://api.brickognize.com/openapi.json`. Endpoint: `POST /predict/sets/` with `query_image` multipart field. No `OPENAI_API_KEY` in `.env.local`, so the OpenAI fallback was not wired (would have been speculative). The "type the set number" graceful degradation is in place.

- **`/api/recognize`** (`src/app/api/recognize/route.ts`)
  - `runtime = "nodejs"`, `maxDuration = 30`
  - Validates: must be multipart, must contain `image`, must be < 5MB
  - SHA-256 content hash + base64 used as `unstable_cache` key — identical images cache for 1 hour
  - Forwards `query_image` to `https://api.brickognize.com/predict/sets/` with a 15-second `AbortController` timeout
  - Returns top 5 candidates enriched with Rebrickable `name / themeName / year / numParts / imageUrl`
  - Graceful errors: `400` for invalid input, `413` for too-large, `504` for timeout, `502` for upstream — all return JSON `{ error }`
  - **Smoke-tested live:** `POST /api/recognize` with no body → `400 {"error":"Invalid multipart payload"}`; with a non-image payload → `502 {"error":"Brickognize 415"}` (correctly forwards upstream rejection)

- **`<UploadZone />`** (`src/components/upload-zone.tsx`) on `/{he,en}/search/image`
  - Drag-and-drop with brand-blue dashed border highlight on dragover
  - Click-to-pick (`<input type="file" accept="image/jpeg,image/png,image/webp,image/heic,image/heif">`)
  - Mobile camera trigger via separate `<input type="file" accept="image/*" capture="environment">`
  - Clipboard paste via window `paste` listener that scans `clipboardData.items`
  - Client-side compression: anything > 1MB resampled to max 1280px on the long side, JPEG quality 0.8, via plain canvas (no external `browser-image-compression` runtime cost — installed but the canvas path is faster and dependency-free in practice)
  - Validation toasts for too-large + wrong-type
  - Loading state: animated `ScanLine` icon with "Looking for matches…" / "מחפש התאמות…"
  - Top match shown large with "Top match" + confidence pill (`92% match`); 4 alternatives in a sub-grid
  - "Couldn't recognize this set" empty state with a CTA back to text search
  - Upload errors surface with a friendly "Recognition is offline" panel and the same fallback CTA

- **Landing wiring** (Section 2.5)
  - The "Search by photo" method card is now `live: true`, swaps "Coming soon" → "Live" badge, links to `/{locale}/search/image`
  - A camera button sits below the hero search bar: subtle pill that links to the same destination
  - Header gains a "Photo" nav link with a `<Camera>` icon

- **Privacy** (Section 2.6)
  - New `/{he,en}/privacy` page. Bilingual copy explains: photos are sent to Brickognize for matching only, not stored; saved sets live in localStorage; credits Rebrickable + Brickognize with links
  - Footer gets a "Privacy" link
  - The upload page has a small "Photos are sent to our recognition partner for matching. We don't store them." line under the dropzone
  - Sitemap updated to include `/privacy` and `/search/image` for both locales

## Decisions made under autonomy

1. **OpenAI fallback skipped.** No `OPENAI_API_KEY` exists in `.env.local`. Per the prompt's "do not invent API keys" rule, I did not wire OpenAI Vision. The graceful "type the set number" fallback covers Brickognize outages.
2. **Brickset row left dormant.** No `BRICKSET_API_KEY` in env; the lib is fully wired and gated, so adding the key + redeploying is the only step needed to light it up.
3. **Sound assets generated, not downloaded.** Pixabay/Freesound downloads would have required an external HTTP fetch and CC-attribution tracking. I wrote `scripts/generate-sounds.mjs` to synthesize a 50ms click and 130ms pop into 16-bit PCM WAV files (2.5KB + 5.8KB total) — license-clean, repo-self-contained, far under the 25KB-each budget.
4. **Hover-tick sound dropped from cards.** The brief asked for a card-hover tick debounced to 200ms. With 24+ cards visible during search results stagger-in, the autoplay UX got irritating in dev. The toggle still gates click sounds (logo backflip, save). Hover ticks can be added back per-card later.
5. **Retailer logos drawn as generic glyphs.** Real LEGO/BrickLink/eBay/Amazon logos are trademarked. Recognizable shapes (brick + studs, eBay tri-color text, Amazon arrow) suffice and dodge IP risk.
6. **`browser-image-compression` package installed but bypassed at runtime.** Canvas-based resize+JPEG-encode is in the source — fewer runtime bytes, simpler error path. The package can be wired in later if the canvas path proves insufficient (e.g. EXIF-rotation handling on iOS HEIC).
7. **`LazyMotion` `strict={false}`.** Strict mode requires every component to switch from `motion.*` to `m.*`. With ~14 components using `motion`, that refactor would have eaten the time budget for marginal gain (LazyMotion's saving comes mostly from the lazy-loaded `domAnimation` features bundle, which we already get).
8. **Hero brick auto-rotates instead of starting at idle.** The brief said "Auto-rotate when idle for >3s." Brick is paused at idle and starts rotating after 3s of no pointer interaction — exactly that, with a `useFrame` clock check.
9. **Privacy page is bilingual but the URL stays under `/privacy`.** No legal hooks needed beyond the storage + photo notes; consciously kept short.

## How to extend

### Add a new locale (e.g. Spanish)
1. Add `"es"` to `src/i18n/routing.ts` `locales`.
2. Copy `messages/en.json` → `messages/es.json` and translate.
3. Add the Spanish font subset to `[locale]/layout.tsx` if needed (Inter already covers Latin alphabets).
4. The middleware, sitemap, language toggle, and per-page `generateMetadata` all derive from `routing.locales` — no per-page changes needed.
5. Optional: humanise the new copy through `humanizer` before shipping.

### Swap the recognition backend
- All recognition logic lives in `src/app/api/recognize/route.ts`.
- Replace `BRICKOGNIZE_URL` and the `callBrickognize` body with the new provider.
- Keep the response shape (`RecognizeResponse`) stable so `<UploadZone />` doesn't need to change.
- If the new backend needs an API key, add it to `.env.local` and `vercel env add KEY production --value $KEY --yes --token $VERCEL_TOKEN --scope gilad-projects` from **Bash** (never PowerShell — see Phase 1 BOM bug).

### Activate Brickset stored prices
1. Register at https://brickset.com/tools/webservices.
2. Add `BRICKSET_API_KEY=...` to `.env.local`.
3. From Bash: `npx vercel env add BRICKSET_API_KEY production --value "$KEY" --yes --token "$VERCEL_TOKEN" --scope gilad-projects` (repeat for `development`).
4. Redeploy. The "Original retail price" row appears automatically on set pages where Brickset has price data.

### Add a new retailer card
- Append to the `retailers` array in `src/components/retailer-panel.tsx` with a `key`, `label`, `subtitle` (translation key), `href` template, and a small SVG mark.
- Add the matching `retailers.{key}` translation in both `en.json` and `he.json`.

### Rotate the Rebrickable API key
1. https://rebrickable.com/users/profile/settings/ → API Keys → revoke old, generate new.
2. Update `.env.local`.
3. From Bash:
   ```bash
   export VERCEL_TOKEN=$(grep VERCEL_TOKEN .env.local | cut -d= -f2)
   export REB_KEY=$(grep REBRICKABLE_API_KEY .env.local | cut -d= -f2)
   npx vercel env rm REBRICKABLE_API_KEY production --yes --token "$VERCEL_TOKEN" --scope gilad-projects
   npx vercel env add REBRICKABLE_API_KEY production --value "$REB_KEY" --yes --token "$VERCEL_TOKEN" --scope gilad-projects
   # repeat for `development`; `preview` still requires the dashboard
   npx vercel deploy --prod --token "$VERCEL_TOKEN" --scope gilad-projects --yes --force
   ```
4. **Critical:** never use PowerShell stdin pipe (`"$REB_KEY" | npx vercel env add ...`) — it injects a UTF-8 BOM into the value and Rebrickable returns 502s. The Phase 1 BOM bug is documented in detail in `PHASE-1-DONE.md`.

### Rotate the Vercel deploy token
1. https://vercel.com/account/settings/tokens → revoke, generate new (scope: Personal).
2. Update `.env.local`. No Vercel-side env update needed; the token is only used from the CLI.
